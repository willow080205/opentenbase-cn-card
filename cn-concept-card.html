把 CN 讲明白

OpenTenBase 分布式数据库 · 图解卡片（题目 2） · 概念：CN（Coordinator Node，协调节点）
小组成员：李佳锐 · 陈钰婵 · 柳雨涵　·　组号：21　·　完成日期：2026 年 11 月 7 日
看图先看这一点：CN 不保存实际的业务数据，只保存系统的全局元数据——业务数据全部分片（Shard）放在 DN 里。所以 CN 干的只有四件事：接单（解析）→ 排活（规划路由）→ 派活（下推执行）→ 收活（汇总结果）。

一句话解释

CN 是 OpenTenBase 集群的协调节点。业务永远连到 CN：客户端用标准 PostgreSQL 协议把 SQL 发给它，它先解析重写这条语句，再由规划器判断这条 SQL 涉及哪些分片（分片路由），把查询切成片段下推给对应的 DN 本地并发执行，最后把各 DN 返回的结果汇总成最终答案交回客户端。CN 和 DN 共用同一套 schema，所以 CN 不需要持有业务数据就能完成解析与规划——它只保存系统的全局元数据（官方文档原话：「CN 上只存储系统的全局元数据，并不存储实际的业务数据」）。CN 也不独自管理事务的全局秩序：全局事务号和一致性快照由 GTM 统一分配，CN 通过连接池模块（poolmgr.c / gtm.c）向 GTM 申请。对外的 CN 不是一个节点，而是多台位置对等的协调节点组成的集群，每个 CN 都提供相同的数据库视图。

生活类比（只映射结构，不要外推）

CN 像一个项目经理：客户提需求（SQL 进来），项目经理看懂需求（① 解析）、判断这件事要找哪些人做（② 规划路由）、把任务拆给对应的开发（③ 下推给 DN），最后把大家的产出拼成完整交付（汇总结果）。而「给每个任务编全局唯一号、保证大家看到的是同一份进度」（GXID 与全局快照）由另一个角色——GTM——负责，项目经理只是去它那里领号。
边界声明：类比到此为止。项目经理会不会请假、忙不过来怎么办，属于高可用问题，本项目文档未在此展开，不要从类比里推出任何关于故障或性能的结论。

常见误解

  • 误解一：「CN 是主库，业务数据存在 CN 上。」
    不对。业务数据的分片存放在 DN 上（如 Shard 0–4095、4096–8191……）；CN 只保存系统的全局元数据，不保存实际的业务数据。
  • 误解二：「CN 是一台机器。」
    不对。CN 是协调节点集群，多个节点位置对等，每个节点都提供相同的数据库视图。
  • 误解三：「CN 自己管事务。」
    不对。全局事务号与全局一致性快照由 GTM 统一管理与分配，CN 只是 GTM 的客户端。
  • 误解四：「算都得拿回 CN 做，DN 只负责存。」
    不对。执行算子会下推到 DN 本地并发执行（算子并行下推、索引加速），CN 只收拢结果。

来源分三级：【官方文档】= 官网快速入门；【仓库 README】= GitHub 仓库首页；【架构图】= 项目《分布式数据库内核架构全景图》（本次现场拍摄，用于补充实现细节）。

1. CN 不存业务数据，只存全局元数据 ——【官方文档】

原文：「在功能上 CN 上只存储系统的全局元数据，并不存储实际的业务数据。」
同义英文表述见【仓库 README】：「the CoordinateNode contains only metadata」「All user data resides in the DataNode」。

2. 用户的 SQL 总是发给 CN，由 CN 切分、下发、汇总 ——【仓库 README】

原文：「Users always connect to the CoordinateNodes, which divides up the query into fragments that are executed in the DataNodes, and collects the results.」
同段另有：「The CoordinateNodes and DataNodes share the same schema.」（对应卡片中「CN 与 DN 共用同一套 schema」一句）

3. CN 是多个位置对等的节点，视图一致 ——【官方文档】

原文：「多个节点位置对等，每个节点都提供相同的数据库视图。」

4. DN 存业务数据分片，并执行 CN 分发的请求 ——【官方文档】

原文：「每个节点还存储业务数据的分片……DN 节点负责完成执行协调节点分发的执行请求。」

5. GTM 管理集群事务信息与全局对象 ——【官方文档】

原文：「GTM：全局事务管理器（Global Transaction Manager）负责管理集群事务信息，同时管理集群的全局对象，比如序列等。」

6. CN 的四大模块与源码路径、CN↔GTM 的 GXID / 快照交互、算子并行下推、分片区间 ——【架构图】
